# 路衡 · 办公智能体 0.4

本地优先、自有品牌的办公智能体桌面原型。普通使用入口是中文 Electron 窗口；高速公路养护样例全部为虚构测试数据。底层任务/模型/工具可用于其他办公场景，不绑定某一单位的真实制度。

**这仍是开发原型，不是已经验收的生产客户端或已签名 Windows 安装包。** Linux 本机运行、测试、范围和未完成项见 `docs/TEST-REPORT.md` 与 `docs/IMPLEMENTATION-STATUS.md`。

## 本版实际能力

- OpenAI 兼容的有界工具调用循环：模型规划 → 受限工具 → 结果回传 → 再规划，最多8轮主模型调用，另有操作次数预算
- 自定义角色名称、职责、性格、启停和9项权限；各角色可继承全局模型或配置独立模型/内存Key
- 共享知识与角色私有知识。私有资料读取后会标记整个任务，禁止再把其摘要转交其他角色；角色委派只传递共同可读资料
- SQLite 持久任务、步骤、来源、审批、提醒、审计、邮件与浏览器状态；任务并发上限2，未完成任务最多30
- 一次性本机提醒与持久周期任务：分钟间隔、每天、每周、明确IANA时区，编辑/暂停/恢复/取消；错过的周期合并为最近一次，避免重启后积压执行
- 真 IMAP/SMTP：强制 TLS 或 STARTTLS、INBOX MIME纯文本读取、UIDVALIDITY/UID游标、纯文本草稿、绑定完整收发件人/服务商/主题/正文的人工审批
- 邮件发送持久化状态机：并发批准只发送一次；DATA开始后断线/取消转为unknown，禁止自动重发。SMTP确认接收不表示对方已读或最终入箱
- 通用受控浏览器：明确目标白名单、每会话独立Chromium、DNS固定转发、观察文本/截图/控件ID；任何填入和点击都先审批
- 人工浏览器接管：独占内存租约，智能体暂停；归还时重新观察、旧输入审批失效，模型重新规划后仍需新审批
- 工作区文本产出、已完成任务的DOCX报告与XLSX执行台账、原生文件下载。任意代码、Shell和任意文件访问未开放
- 桌面端可明确选择关闭后在托盘继续运行；默认关闭即退出。系统安全存储可用时可明确保存当前凭据的加密快照，默认仅内存
- 中文任务/角色/知识/邮件/浏览器/日志/设置界面。确定性任务演示模式不使用模型；手动真实邮件与浏览器工作区独立于任务演示模式

## 安全与实际边界

1. **单用户本机**：只监听127.0.0.1；没有多人后台、单位SSO或用户级资源ACL，不能直接暴露公网
2. **凭据默认仅内存**：模型Key和邮箱凭据不写数据库或浏览器存储。桌面端可明确保存当前全部凭据的系统加密快照；后续修改不会自动保存，需再次确认。快照绑定服务与账号，配置变化跳过恢复。安全密钥库不可用时拒绝保存，不允许明文回退；Linux basic_text明确拒绝。忘记快照不清除当前运行的内存凭据，退出会清除内存。旧密钥可能为迟到响应脱敏保留至进程退出
3. **真实服务尚未验收**：真实模型尚未完成认证及工具闭环，真实邮箱或单位网站尚未联调。已有模型协议、邮件TLS协议与网站行为验证主要使用可控夹具
4. **受控浏览器有限制**：生产配置只允许公网HTTPS443，拒绝私网/回环/保留地址；内网单位OA需之后由管理员设计批准的网络白名单。测试HTTP回环例外只能由测试构造器启用，网页API不能开启
5. 浏览器不导入现有Cookie/登录态，不执行用户或模型提供的JS/选择器，不下载/上传文件，不输入密码、验证码、银行卡或凭据字段。人工模式也不开放这些字段
6. 不支持需要未经审批POST才能加载的网页、复杂登录/SSO、验证码、跨站第三方依赖和全部网页组件。已确认输入动作不等于业务系统保存成功，必须依据页面结果验证
7. 浏览器会话不跨重启导入或重放。中断的输入结果未知时要求人工核实；等待中的旧审批失效
8. **没有OS级代码沙箱**：Node本身不是代码隔离容器。因此任意代码执行被禁用，不应把受限工作区当成安全代码沙箱
9. **非24小时云服务**：默认关窗口即停。桌面明确开启托盘运行且托盘可用后，关闭窗口会继续本机任务；托盘“退出”真正停止。没有开机自启、多设备推送或云后台。电脑休眠/关机时不能执行；重启会合并补做最近一次周期，旧任务审批不会绕过
10. **操作预算不是金额上限**：当前控制调用次数；用户配置的模型服务按自己的规则计费
11. 本地数据库未做静态加密、企业防篡改审计或正式灾备。所有资料应遵守单位保密和数据外发要求
12. API模式会把任务和执行需要的资料传给该角色配置的模型服务。角色隔离不是对第三方模型服务商的隐私保证
13. 浏览器模块完成功能与策略限制用例，不等于完成独立安全审查；通用浏览器的独立安全复核尚未完成，不能直接上线生产

## 从源码运行

开发机需要Node.js24.5+；浏览器/桌面验证需要图形主机允许Chromium沙箱和Unix socket。邮件TLS测试需要OpenSSL命令行工具，应用运行本身不依赖它。

```bash
npm ci
npx playwright install chromium
npm start
```

开发浏览器入口为 `http://127.0.0.1:4318`。这是运行该程序那台电脑的本地地址，不是远程公网链接。可用 `node server.mjs --port 4319` 调整端口，`HIGHWAY_DATA_DIR` 设置独立数据目录。

独立桌面窗口：

```bash
npm --prefix desktop ci
npm --prefix desktop run install:runtime
npm --prefix desktop start
```

Electron内置Node24/SQLite，通过utility process启动后端；最终打包用户不需要单独安装Node、Python或npm。上述命令只用于开发源码。`docs/DESKTOP.md` 提供Windows离线NSIS构建步骤；浏览器、Node、邮件依赖都应在构建阶段装进包内，运行时不自动下载。

Linux已验证目录包及其运行库来源见 `docs/DESKTOP.md`；它不等于Windows安装器，也不保证其他Linux发行版直接兼容。普通体验说明见 `docs/QUICKSTART.zh-CN.md`。

## 建议体验顺序

1. 在任务演示模式提交“汇总演示养护待办并生成周报”，查看步骤、来源并下载真实文本产物
2. 使用内置模拟OA任务，先拒绝一次，再体验人工接管、归还和批准写入
3. 新建自定义角色，设置权限和私有知识，验证权限不足会停止且不假报成功
4. 配置自己的模型服务后，可让模型自主选择安全工具；未提供Key的测试不应被当作真实模型质量验证
5. 邮件工作台需用户自己的服务器/账号及本次运行密码；阅读明确连接范围，先读信、起草，再核对完整快照批准。不要把测试邮箱地址用于真实发送
6. 浏览器工作台只配置明确授权的目标；观察后按控件ID提出精确动作，批准前不会触发输入。生产网站、内网网络与认证要逐个验收

## 模块结构

- `server.mjs`：环回HTTP、会话和同源校验、界面/API
- `lib/engine.mjs`：任务、工具、预算、角色委派、审批与恢复
- `lib/schedules.mjs`：持久周期、时区、错过合并与幂等实例
- `lib/office-artifacts.mjs`：无宏DOCX/XLSX文件生成
- `lib/persisted-credentials.mjs`：模型/角色/邮箱配置绑定的加密快照桥接
- `lib/model.mjs`：OpenAI兼容协议、HTTPS和DNS固定
- `lib/agent-authority.mjs`：独立模型配置、内存凭据、角色知识可见性
- `lib/mail-adapter.mjs`：TLS邮件协议、游标、完整审批和Outbox
- `lib/controlled-browser.mjs`：目标网络策略、隔离会话、opaque控件、精确输入审批和人工租约
- `lib/browser.mjs`：原有本地模拟OA闭环
- `desktop/`：安全Electron壳与离线包构建配方
