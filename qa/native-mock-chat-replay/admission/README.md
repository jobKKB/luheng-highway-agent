# Exact 0.7.1 mocked-model consumer admission

This directory is consumer-only. It never rebuilds, wraps, repairs, launches,
installs, signs, uploads, publishes, or downloads a product. It has no external
Python dependencies. The parent workflow owns all native execution.

## Scope and source

`contract.json` and independently embedded constants freeze producer run
37773394370, attempt 1, controller head
441086c414182d204e438df598ad8f967cd23761; payload source
c3490f7ffe0eaa501aa1e20c55e84fd5180e66dd; exact 0.7.1 release EXE,
evidence artifact, original evidence files, and original 117874-file inventory.
The public preview release is unsigned and has updates enabled in `nsis-preview`
mode. Disabled-update predicates from the older 0.0.0 consumer do not apply.

The evidence qualification checks are adapted from `qualify()` in
[the immutable reviewed online-update validator](https://github.com/jobKKB/luheng-highway-agent/blob/589eb5bdc8fc66569500903ca733c4e01dd592db/qa/release-windows/verify-online-update.py).
Its reviewed text is retained as `reviewed-upstream.py.txt` for comparison only;
it is never dynamically imported or executed. The standalone validator narrows
that authority to the single reviewed 0.7.1 artifact and adds API release-asset,
attempt, generated-file, current-run, token, and scope checks.

The producer's original restricted-token proof remains frozen and independently
required. New mocked-model native work has the separate scope
`elevated-runner-explicitly-limited`. It cannot claim a real provider, LLM quality,
standard-account installation, offline operation, physical IME or updater
acceptance. Original ordinary launch evidence does not turn the new CDP-assisted
mock test into a plain-launch test.

## CLI contract

Every mode requires `--contract FILE --output FRESH_JSON`.

- `contract`: validates immutable pins and returns `minimum_scratch_bytes`
- `api --api-root DIR`: reads fresh GitHub JSON snapshots named
  `producer-run.json`, `evidence-artifact.json`, and `release.json`; requires
  completed/successful exact producer/attempt/head, exact unexpired evidence
  artifact identity/digest/size, and exact published preview release and EXE
  asset ID/digest/size/download URL
- `evidence --evidence EXTRACTED_ROOT`: hashes all five original receipts, checks
  source identity, every manifest row, policy, native startup, installer custody
  and independently qualified original restricted-token lifecycle
- `downloads --evidence EXTRACTED_ROOT --installer EXE`: performs evidence checks,
  then hashes the whole EXE against its exact basename/size/SHA-256. Writes
  `installer-build.relocated.json` beside `--output`, or at an explicit
  `--relocated-receipt FILE`; only the installer path changes. The destination
  must be outside the immutable original evidence tree. Original receipt bytes
  are rechecked after writing
- `tree --evidence EXTRACTED_ROOT --root INSTALL --uninstaller BASENAME`:
  hashes every original installed file plus the reviewed exact generated
  `Uninstall LuhengOfficeAgent.exe` and `resources/package-type`. No extra,
  missing, mutated, aliased, hard-linked, symbolic-link or reparse-point files
  are accepted. Ordinary empty directories remain allowed because the producer
  manifest inventories files, not directories
- `acceptance --evidence EXTRACTED_ROOT --root CURRENT_EVIDENCE --current-run ID`:
  re-admits original proof; requires the current run's complete native lifecycle,
  same-user/integrity tokens including the mock controller, both exact-tree
  receipts and basic mock receipt/scope. Returns `base_lifecycle_only: true`.
  The separate Node protocol, rendered response, screenshot and debugger-owner
  verifier is additionally mandatory for complete mocked-model acceptance

All output paths must be fresh. Any bad input causes nonzero exit and does not
mint a success receipt. An existing output is preserved and causes failure;
callers must check the process exit code. JSON duplicate keys and nonfinite
values are rejected. None of these modes treats API metadata alone as proof
of downloaded executable bytes.

## Verification

Run `python -I -S -B admission/selftest_verify_mock.py` from any working directory.
Ten synthetic suites include 171 fail-closed negative cases, plus CLI nonzero /
no-receipt / stale-output checks. They exercise exact contract repins, API
mutations, re-pinned inconsistent evidence, enabled preview policy, token scope,
source identity, exact trees, NSIS generated bytes, symlink/hardlink/case aliases,
current-run freshness and path-only relocation. The suite uses tiny fake byte
fixtures and never executes any product. It creates symbolic links in temporary
directories; the Windows lane must retain its declared elevated hosted-runner
context for these tests.

Local `validation/admission-*` results additionally bind actual existing evidence
ZIP bytes, live read-only GitHub API snapshots, original manifest totals, and
original before/after generated-file identity. No 1.59 GB installer was downloaded
locally, and no native mock-chat run has been performed by this admission work.
